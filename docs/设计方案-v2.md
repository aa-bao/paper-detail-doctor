## 1. 定位与边界

**一句话定位**：面向"已经有一份 Word 论文"的人，把格式、排版、引注、体例、结构上的问题**诊断出来并修好**，且**不破坏你已经手改过的内容**。

**服务对象**：以"只有 docx、要交作业/投稿/返修"的人为默认用户；"从 0 开始写"是次要场景。

**不做**：不生成论文内容（`academic-paper` 已覆盖）、不做文献检索、不做查重。

## 2. 核心架构：docx 是唯一真值源

这是 v2 相对 v1 的根本改动。你提的问题本质是：**文档进入"人机共同编辑"状态后，任何"重新生成"都会丢人工修改**。所以架构必须反过来 —— **不再有"生成"这个动作，只有"手术"**。

### 2.1 双通道，各管一段生命周期

```
阶段一：从 0 搭初稿           阶段二：反复返修（长期，主要场景）
──────────────────           ──────────────────────────────
md 源 ──[建通道]──▶ docx  ──▶ docx ──[改通道]──▶ docx ──[改通道]──▶ docx
                               ▲  人工直接改 docx      ▲  人工再改
                               └──────────────────────┘
```

| 通道 | 输入 | 输出 | 使用频率 | 特点 |
|---|---|---|---|---|
| **建通道**（Markdown → Word） | md 目录 + 模板 | 一份全新的 docx | **一次性**，稿子起步时用 | 会重建文档，所以**只能对"还没有人工痕迹"的稿子用** |
| **改通道**（docx → docx 手术） | 现有 docx | 同一份 docx 被定点修补 | **长期、反复** | 不重建、不重排、只动目标节点；**人工改动不会丢** |

关键约定：**一旦稿子进入人工修改阶段，就只用改通道，永远不要再跑建通道**（否则等于覆盖）。这一点会写进 SKILL.md 的显著位置，作为硬性提示。

### 2.2 三条铁律

| # | 铁律 | 含义 | 怎么保证 |
|---|---|---|---|
| 1 | **幂等** | 同一个修复跑 1 次和跑 5 次，结果完全一样 | 每个操作执行前先检测"是否已经做过了"（如建书签前查重名、设上标前查 `vertAlign`），已存在就跳过并计入 `skipped` |
| 2 | **最小侵入** | 不动目标之外的任何东西 | 只改 OOXML 里的目标节点；不重排段落、不重建样式、不重设页面、不碰未经许可的 run |
| 3 | **可回滚** | 任何写入前都有快照 | 每次 apply 前自动把 docx 复制到 `_backup/<YYYYMMDD-HHMMSS>/`，并打印回滚命令 |

### 2.3 三段式协议：audit → plan → apply

这是解决"怕被覆盖"的直接手段 —— **诊断和修改分离，中间必须经你确认**。

| 段 | 动作 | 是否写盘 | 产物 |
|---|---|---|---|
| **audit** | 只读扫描 docx，按 §4 清单逐项检查 | ❌ 只读 | `audit-report.md` + `audit.json`（每条问题带定位） |
| **plan** | 把问题翻译成"待执行操作列表"，你来勾选/排除 | ❌ 只读 | `plan.yaml`（可编辑：勾掉不想改的、调参数） |
| **apply** | 按 plan 逐条执行手术，每条两次断言 | ✅ 写入（先快照） | 改后的 docx + `apply-log.json`（做了/跳过了哪些） |

**默认行为**：只跑 audit 就把报告给你。**不跑 apply 就绝不会改你的文件**。

### 2.4 为什么"状态驱动"能救回人工改动

v1 的思路是"记录我上次改了什么 → 这次重放"（补丁驱动）。这确实会跟你的人工改动打架。

v2 改成**状态驱动**：audit 从不问"相比上次变了什么"，只问一个问题 —— **"你现在的样子，符不符合规范？"**

- 你手改了一处引注编号 → audit 照当前状态判定，发现编号断号 → 报出来
- 你故意保留某处圆括号引注 → audit 报"不符合体例"，但你可以把它标记为保留（见 §2.5），apply 就跳过
- 你删掉一整个小节 → 不需要任何"差异检测"，audit 直接发现该节标题缺失 / 引注编号断裂

**这也是为什么"人工改过 docx"完全不是问题**：状态驱动天然只关心现状，不关心历史。

### 2.5 误报抑制：`.thesisignore`

审计报告里每一条问题都会带一个稳定 ID（如 `cite-locate-0042`）。
你可以把"我就是要这样写"的条目写进稿子同目录的 `.thesisignore`：

```yaml
# .thesisignore —— 人工裁定保留，apply 一律跳过
- id: cite-locate-0042        # 这一处圆括号引注是刻意的
  reason: 导师要求此处用文中注
- rule: dash-density          # 整条规则对我这篇不适用
  reason: 本文是文艺学论文，破折号本就多
```

这让"工具规范"和"作者意图"不再互相打架。

## 3. 检查标准从哪来：模板驱动（并入 paper-template-extractor）

### 3.1 为什么必须并入

v1 最大的隐患是：那些阈值和体例（上标、句读前引注、破折号 ≤2.5‰、直引号）**全是本次会话里你逐条拍板的，换个学校/换个导师就全不成立**。标准不该是我内置的偏好，应该来自**学校给的模板或规范文件**。

所以 `paper-template-extractor` 不再是一个独立工具，而是这个包的**标准来源（source of standards）**，位于流水线最上游：

```
学校模板.docx / 格式规范.pdf / 范文.pdf
        │
        ▼  paper-template-extractor（并入）
   template-spec.json    ← 命名样式 + 版式参数 + 体例规则
        │
        ├──▶ 建通道：按 spec 生成 docx
        └──▶ 审计器：spec 里的值就是"期望值"，docx 是"实际值"，两者比对
```

### 3.2 模板要提取的东西（在现有能力上扩展）

现有提取能力：命名样式（字体/字号/行距/缩进/对齐）、页面设置。

**需要新增提取的"体例规则"**（都是 §4 检查项的期望值来源）：

| 规则键 | 取值示例 | 从哪读 |
|---|---|---|
| `bibliography.system` | 顺序编码制 / 著者-出版年制 | 范文的引注与文献表形态 ← **你第 6 点要的** |
| `citation.style` | 上标方括号 / 行内方括号 / 圆括号 / 上标数字 | 范文正文 |
| `citation.position` | 句读前 / 句读后 | 范文正文 |
| `caption.figure` | 图题在下、格式「图 1-1」 | 范文图表 |
| `caption.table` | 表题在上、格式「表 3-1」 | 范文图表 |
| `header.content` | 论文题目 / 学校名 / 空 | 范文页眉 |
| `header.rule` | 有横线 / 无横线；线型、粗细 | 范文页眉 |
| `numbering.heading` | 手工编号 / 样式自动编号；「第1章」vs「1.」 | 范文标题 |
| `abstract.limit` | 摘要字数上限、是否单页 | 范文摘要 |
| `section.page_numbering` | 分节页码方案（封面无 / 摘要罗马 / 正文阿拉伯） | 范文页码 |

**三级优先（你第 6 点的落地）**：

```
① 模板 spec 里读到的规则        ← 最高优先，"学校说了算"
② 项目级配置 config.yaml 的覆盖  ← 你手动指定，"我导师另有要求"
③ GB/T 7714（文献）+ 通用学术惯例 ← 兜底，且必须在报告里标注"标准来源：默认"
```

审计报告每一条都会写清 `标准来源: 模板 / 配置 / 默认`，这样你一眼能看出哪些判定是"学校规定"、哪些只是"通用建议"。

### 3.3 模板缺失时的降级

拿不到模板/范文时：用 ③ 兜底，并在报告顶部显著标注：

> ⚠️ 未找到模板或格式规范文件，以下判定基于通用学术惯例，可能与贵校要求不符。

不静默用默认值假装合规。

## 5. 开题报告—正文一致性核对（你要审的部分）

先直接回答你问的两个问题。

### 5.1 「你是怎么进行核对的」——锚点法

不做"全文语义比对"（那样既不可复核也说不清）。做法是：**从开题报告里抽出有限个可指定的锚点，再回正文里找它们的落点。**

**七类锚点**（每类都预先定义"怎么抽、怎么找、怎么判"）：

| 类 | 锚点 | 在开题哪里抽 | 在正文哪里找 | 判定层 |
|---|---|---|---|---|
| A1 | 论文题目 | 封面 | 封面 | L1 字面 |
| A2 | 核心概念 / 关键词 | 概念界定、关键词 | 第 1 章概念界定、第 2 章框架 | L1 + L2 |
| A3 | 理论基础与学者 | 理论基础节 | 理论/框架章 | L1 + L2 |
| A4 | 研究方法要素（方法、对象、样本量、地点、时间） | 研究方法节 | 研究方法节 | **L1 数字为主** |
| A5 | 章节大纲 | 论文框架节 | 实际目录 | L3 结构 |
| A6 | 预期结论 / 研究假设 | 研究意义、预期结论 | 结论章 | L2 语义 |
| A7 | 文献承诺（数量、关键文献） | 参考文献节 | 文献表 | L1 数字 + 名单 |

> **落地时的调整（2026-09-17，A6 阶段）**：上表定义的是**锚点的类别**；
> 而"题眼是哪个词、点了哪些核心概念、引了哪些理论家、方法要素有哪些、
> 大纲里哪一章被并了节"——**这些是某一篇论文的数据，不是工具的知识**。
> 所以它们**外置为「锚点档案」`assets/anchors.yaml`**，代码里不写死任何一篇论文的
> 具体值。未配置的锚点**一律产出「无法判定」交人工**，绝不静默判成一致。
> 这样同一套检查逻辑可以用于任何一对"开题报告 docx + 正文 docx"。

### 5.2 「怎么判断一致」——三层判定

| 层 | 判什么 | 怎么判 | 自动化程度 |
|---|---|---|---|
| **L1 字面** | 术语、数字、标题、人名 | 归一化（去空白/标点/全半角）后子串或近义匹配；数字严格相等 | 全自动，结果确定可复核 |
| **L2 语义** | 同一命题在两处的表述是否等价（如开题"并非孝道衰落而是适应策略" ↔ 正文 3.4 节的表述） | LLM 判定，**强制输出**：双方原文引用 + 置信度 + 判定理由 | 半自动，置信度低转人工 |
| **L3 结构** | 大纲覆盖矩阵：开题每个章/节 → 正文对应哪一节 | 大纲树 ↔ 实际标题树做映射 | 全自动 |

**判"一致"的定义（写死，不含糊）**：

- L1：归一化后字符级匹配成功 → 一致；数字不等 → **改动**。
- L2：三选一 —— `等价` / `不等价` / `无法判定`。判定为 `等价` 需要 LLM 给出"两处指向同一命题"的理由；置信度 < 0.7 一律归入 `无法判定`，转人工。**不给"差不多一致"这种模糊结论。**
- L3：开题某节在正文有对应标题 → 覆盖；无对应 → **缺失**。

### 5.3 五类结论（每条锚点必落其一）

| 结论 | 定义 | 风险 | 处置建议 |
|---|---|---|---|
| **一致** | L1/L2/L3 均通过 | —— | 无需动作 |
| **偏离** | 正文有、开题没有 | 中 | 答辩时需准备说明理由 |
| **缺失** | 开题有、正文没有 | **高** | 最易被问；建议补写或书面说明 |
| **改动** | 两边都有但不一致（六章→五章、30–40 人→15 人） | 中高 | 需交代改动理由，且要自洽 |
| **无法判定** | 定位失败或 L2 置信度低 | —— | **必须人工过一遍**，不许静默丢弃 |

### 5.4 报告形态：可复核的"证据卡"

一对一卡片，而不是笼统结论。每条必须同时给出两边原文，让你能自己判断：

```
[A4-03] 样本量                              结论：改动 ⚠️
  开题（研究方法节）:
```

### 5.5 「怎么评判这个能力好不好」——金标准回归

你说要评判效果，所以这个能力**必须自带评分机制**，而不是靠感觉。

**金标准哪来**：本次会话我已经用人工方式核过一遍，产出 8 个对齐锚点 + 4 处差异（记录在 `.workbuddy/memory/2026-09-17.md`）。**这 4 处差异就是现成的金标准**，直接固化为测试样本：

```yaml
# tests/golden/proposal-consistency.yaml
case: 样例论文
expected:
  一致:
    - {anchor: A1, value: "题目一致"}
    - {anchor: A2, value: "家庭情感共同体"}
    # … 共 8 条
  差异:
    - {id: A5-01, type: 改动, note: "六章合并为五章"}
    - {id: A5-02, type: 偏离, note: "第2章新增祖辈接棒/收缩阶段两节"}
    - {id: A5-03, type: 缺失, note: "开题第四章节'重点案例分析'未设个案专节"}
    - {id: A4-03, type: 改动, note: "30—40人 → 15人"}
```

**跑分指标**（三选一都不行，三个都要报）：

| 指标 | 含义 | 期望 |
|---|---|---|
| **召回率** | 4 处真差异被检出几个 | 越高越好（漏报最致命） |
| **误报率** | 报了不存在的差异 | 越低越好（误报会让你白费功夫） |
| **定位准确率** | 给出的"正文位置"确实是对的那一处 | 越高越好（给错位置等于没用） |

再加上人工抽检：`无法判定` 桶里的条目，人工过一遍，记录"其中有多少其实可以自动判"。**这告诉你该往哪调阈值。**

首次封装时我会把这套跑分跑出来给你看数字，而不是说"效果不错"。

### 5.6 这个方法的局限（先说清）

1. **它只能查"开题说了、正文没做到"这类结构性问题，不能判断论证质量。**
2. **L2 语义判定依赖 LLM，会有主观性** —— 所以强制带原文引用和置信度，且低置信度一律转人工，不允许它替你下结论。
3. **开题报告本身不完整时（只有一段笼统描述）**,锚点抽不出来，能力会退化。你这篇的开题报告内容很完整（14,779 字、单表格），属于有利情况。
4. **一致性的最终裁定权在你和导师**，工具只负责"把证据摆齐、把该问的问题列出来"。

## 6. 包结构（v2 · 多 skill 包）

### 6.0 这是一个「包」，不是一个「skill」

**你 2026-09-17 澄清**：要的是 skill **包** —— 里面可以不止一个 skill，包根只做**索引**或**工作流执行**。

参照物：本机已有的 `academic-paper` 就是这种包（根 `SKILL.md` + `related_skills` 指向子 skill）。
⚠️ 但那个包的子目录里各自**递归复制了整个包**（`academic-paper-reviewer/academic-paper/academic-paper-reviewer/academic-pipeline/…`，深度到 5 层），是安装过程造成的坏结构。**本包不复制这种模式**：子 skill 目录只放自己的东西，共用代码一律走 `shared/`。

**编排模型 = 两种模式**

| 模式 | 触发 | 行为 |
|---|---|---|
| **索引模式** | 用户提出单点请求（"把引注改成上标"） | 根 `SKILL.md` 的路由表把请求交给对应子 skill，不惊动其他 skill |
| **工作流模式** | 用户提出整体请求（"定稿前帮我查一遍"） | `workflow/` 按固定链路串起子 skill：`template-extract → audit_all → plan → apply` |

**根层职责边界**：`SKILL.md` **不实现任何检查**，只做路由、汇总、编排。检查逻辑全在 `skills/` 下的子 skill 里。否则子 skill 就成了摆设。

### 6.1 7 个子 skill 的划分（按检查层 + 生命周期）

| 子 skill | 职责 | 覆盖 | 标准来源 |
|---|---|---|---|
| `template-extract` | 模板/规范/范文 → Word 模板 + 格式 spec（**体例规则**） | 所有检查的"期望值" | —— |

| `cite-doctor` | 引注位置、形态（上标）、Ctrl+点击跳转、编号制、正反覆盖、GB/T 7714 著录、重复编号 | L2 · 7–13 | 模板 + GB/T 7714 |

### 6.3 工作流与命令形态（预期）

```

```

```
# ① 拿标准（可选；没有就降级到默认规范并显著标注）
python workflow/extract_standard.py --template 学校模板.pdf --out spec/template-spec.json

# ② 只读诊断（绝不写盘）
python workflow/audit_all.py --docx 我的论文.docx --spec spec/template-spec.json

# ③ 生成可编辑的修复计划 → 打开 plan.yaml，把不想改的项 enabled 改成 false
python workflow/plan.py --audit _output/audit.json --out plan.yaml

# ④ 执行（先快照，幂等，可回滚）
python workflow/apply.py --docx 我的论文.docx --plan plan.yaml
```

**关键设计**：`audit / plan / apply` 是三个独立命令，不是一个大脚本。因为"人工审核后再改"是这个包的核心价值，必须能被拆开执行。而且 `audit` 段纯只读 —— **只读永远安全，可以随时重跑**。
