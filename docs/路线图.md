# 路线图：先 A 打通，再 B 分批升级

原则（2026-09-17 拍板）：**A 阶段原样搬运 + 把路径/规则外置成配置，不做重写；B 阶段按价值分批升级为参数化 CLI + yaml 规则外置。**

每个批次交付一个**可独立使用的子 skill**，不是散装脚本 —— 这样任何阶段中断，包里已有的子 skill 都能单独用。

**A1 为什么把目录重构成 `skills/` 子包**：早期骨架把全部代码放在包根的 `scripts/` 里，等于把整套做成**一个** skill。你要的是**包**（可容纳多个 skill），所以包根只留索引与编排，检查逻辑全部下沉到 `skills/<子 skill>/`。

## B 阶段 · 分批升级

优先升 B（最通用、复用率最高）：

1. **`cite-doctor`（L2 引注）** —— 三级优先的体例解析、多种编码制支持
2. **`template-extract`** —— 体例规则的自动识别（从范文反推规则，而非人工填）
3. **`proposal-consistency`** —— 锚点抽取与 L2 语义判定的稳定性

可以长期留在 A 的：

- 项目专属的一次性替换映射（标题平实化等）—— 走 `assets/rules/*.yaml`，不写死在代码里

---

## 验收标准（封装完成的定义）

必须能对**一篇与本项目完全无关的论文**跑通全链路，且**不改任何脚本代码，只改配置**：

1. 指定 docx（或 md 目录）+ 参考文献表 → 一键渲染引注 / 建立跳转
2. `workflow/audit_all.py` 出报告 → 每条带定位、期望/实际对照、标准来源
3. `workflow/plan.py` 出可编辑计划 → `apply.py` 执行 → 幂等复跑结果一致
4. 字数统计报出双口径 + 分章配额差
5. 页眉/目录/PDF 导出链路可用
6. 金标准跑分出三指标数字（召回 / 误报 / 定位准确率）
7. 单点请求能被根 `SKILL.md` 正确路由到对应子 skill，且**不触发其他子 skill**

       （python-docx 写 zip 时给每个条目盖当前时间戳，DOS 精度 2 秒），
       于是同一份 plan 立刻被判"文档哈希已变"，**对已改完的文档重跑 apply 会被拒**；
    ③ 让"幂等跳过不重写文件"这条断言**不确定**：两次保存只要跨过 2 秒刻度，字节就不同
       —— 这就是本轮全量验收里出现过一次、单跑 5 次又复现不了的偶发失败的根因。
  - 修法：只在**真的改了东西**时才重写文件；幂等账本仍按原条件落盘
    （账本是 `.thesis-doctor/` 下的旁挂文件，不重存 docx 不影响它）。
  - **实证**（一次性探针，不入库）：① 内容一字未改只重存一遍 → 哈希 `2e62bb…` → `c9ec62…`，
    **变了**（机制证实）；② 修复后第二批 `changed=0 skipped=1 saved_to=None`，
    哈希与门禁哈希都不变；③ 模拟旧行为（空操作重存）后哈希 `07d4e7…`，
    再用原 plan 跑一次 → 被拒，理由"文档哈希已变（plan 生成于改动前）"，
    **用户会以为是自己手改了稿子，其实是 apply 自己把哈希改了**。

  **Bug 2｜缺 `docx` 字段的 plan 被误拒，且报错信息是编造的**
  - `p_docx = os.path.abspath(plan.get('docx') or '')` —— 缺字段时 `abspath('')` 等于
    **当前工作目录**，于是这种 plan 被当成"为 <cwd> 生成的"而拒掉，并打印一句
    **凭空捏造的路径**。这违反本包自己的纪律（不许说不知道的事）。
  - 修法：只有 plan 真的记录了 `docx` 才做比对；没记录就如实给一条 warn
    "未记录目标文档，无法判断是否套错了文件"。正常路径（`workflow/plan.py` 会写 `docx`）
    不受影响，属**潜伏 bug**；手写的 plan 会撞上。
  - **实证**：修前 `guard_plan` 对同一份 plan 报"plan 是为「F://Coding//Project//paper-detail-doctor」
    生成的"（那其实是 cwd）；修后无 error、给 warn。

  **新增 3 条回归**（`tests/selftest_shared_lib.py`，36 → 39）：
  `plan 缺 docx 字段不被误拒` / `plan 缺 docx 字段如实给 warn（不编造路径）` /
  `报错信息里不出现当前工作目录冒充来源`；并把"幂等跳过也没再改文件"补上 `saved_to` 判据、
  失败时打印前后哈希（原来只报"不等"，查不出为什么）。

  **教训（值得记）**：偶发失败不要当噪声放过去。这次如果按"重跑就好了"处理，
  就会漏掉一个会让用户 plan 失效的真 bug，而且它下次还会以同样的 1/N 概率咬人。
  定位手法是：先问"这条断言在比较什么"，再问"有什么会改变被比较的东西"。
