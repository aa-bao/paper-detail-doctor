# 路线图：先 A 打通，再 B 分批升级

原则（2026-09-17 拍板）：**A 阶段原样搬运 + 把路径/规则外置成配置，不做重写；B 阶段按价值分批升级为参数化 CLI + yaml 规则外置。**

每个批次交付一个**可独立使用的子 skill**，不是散装脚本 —— 这样任何阶段中断，包里已有的子 skill 都能单独用。

---

## A 阶段 · 打通可用

| 批次 | 交付的子 skill / 组件 | 状态 |
|---|---|---|
| **A1** | 包骨架 + git 仓库 + 根 `SKILL.md`（索引与路由）+ `shared/contracts/`（Issue / PlanItem schema）+ 目录重构为多 skill 包 | ✅ 完成 |
| **A2** | `skills/template-extract` —— `paper-template-extractor` 迁入，并扩展**体例规则**提取（编码制、引注形态与位置、题注位置与格式、页眉、页码分节、摘要上限） | ⬜ |
| **A3** | `shared/lib/docx_scan.py` + `shared/lib/report.py` + `skills/cite-doctor` 的**审计**半部（L2 全部 7 项） | ⬜ |
| **A4** | `shared/lib/docx_ops.py` + `shared/lib/ooxml_guard.py` + `skills/cite-doctor` 的**手术**半部 + `workflow/{audit_all,plan,apply}.py` | ⬜ |

**A1 为什么把目录重构成 `skills/` 子包**：早期骨架把全部代码放在包根的 `scripts/` 里，等于把整套做成**一个** skill。你要的是**包**（可容纳多个 skill），所以包根只留索引与编排，检查逻辑全部下沉到 `skills/<子 skill>/`。

## B 阶段 · 分批升级

优先升 B（最通用、复用率最高）：

1. **`cite-doctor`（L2 引注）** —— 三级优先的体例解析、多种编码制支持
2. **`template-extract`** —— 体例规则的自动识别（从范文反推规则，而非人工填）
3. **`proposal-consistency`** —— 锚点抽取与 L2 语义判定的稳定性

可以长期留在 A 的：

- 项目专属的一次性替换映射（标题平实化等）—— 走 `assets/rules/*.yaml`，不写死在代码里

---

## 验收标准（封装完成的定义）

必须能对**一篇与本项目完全无关的论文**跑通全链路，且**不改任何脚本代码，只改配置**：

1. 指定 docx（或 md 目录）+ 参考文献表 → 一键渲染引注 / 建立跳转
2. `workflow/audit_all.py` 出报告 → 每条带定位、期望/实际对照、标准来源
3. `workflow/plan.py` 出可编辑计划 → `apply.py` 执行 → 幂等复跑结果一致
4. 字数统计报出双口径 + 分章配额差
5. 页眉/目录/PDF 导出链路可用
6. 金标准跑分出三指标数字（召回 / 误报 / 定位准确率）
7. 单点请求能被根 `SKILL.md` 正确路由到对应子 skill，且**不触发其他子 skill**
