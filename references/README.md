# references/ —— 跨 skill 的 SOP

这里放**跨 skill 的操作手册**：讲"这件事怎么做对、会踩哪些坑、换一篇论文要改什么"。

**与各子 skill 的 `SKILL.md` 分工明确，不要互相复制**：

| | 回答什么问题 | 住在哪 |
|---|---|---|
| 子 skill 的 `SKILL.md` | 这个 skill **是什么**、有哪些 rule id、CLI 怎么调、产物在哪、**管什么/不管什么** | `skills/<name>/SKILL.md` |
| 本目录的 SOP | **遇到坑怎么办**、为什么这么做、怎么迁移到另一篇论文、跨 skill 的注意事项 | 这里 |

> 一份知识只写一遍。SKILL.md 里写过的 rule 表、参数、产物路径，SOP 里只引用不重抄——
> 两处都写必然漂移。

## 三份 SOP

| 文件 | 讲什么 | 什么时候看 |
|---|---|---|
| `SOP-引注上标与跳转.md` | 引注做成「上标 + 方括号 + Ctrl+单击跳转」：先量化体例基准、两条实现路径、6 个可执行动作、6 个坑（含 WPS 把超链接改写成域代码）、三步验收 | 要让引注能上标显示、能点着跳转时；或 `cite-doctor` 报了 `cite-form` / `cite-jump` 时 |
| `SOP-模板标准.md` | 判定基准从哪来：三级优先（template ＞ config ＞ default）、**实测值 ≠ 上限**这条核心纪律、"宁可少报不可瞎报"、从模板/范文反推 spec 的流水线、6 个提取坑 | 准备跑 `template-extract` 时；或报告里 `standard_source` 全是 `default` 时 |
| `SOP-开题一致性核对.md` | 开题 ↔ 正文核对怎么用：怎么填锚点档案、五类结论各自的动作、L2 怎么交人裁、**怎么对抗性验证它没作弊**、三指标口径与已知折扣 | 答辩前自检；或 `proposal-consistency` 报了一片「无法判定」时 |

## 三条贯穿三份 SOP 的共同纪律

这三条是本包的"性格"，写在代码注释里，也在这里重申：

1. **"没法判"必须说出来，不许伪装成"没问题"。**
   - 没有 spec → 报告顶部明写"本次依据为通用惯例，不代表你学校要求"；
   - 没填锚点 → 一律产「无法判定」，绝不静默跳过；
   - 某条规则抛异常 → 升格为 `audit-internal-error` 的 **error 级** issue，
     并提示"本次结果不可信"。**不许只写进 notes**，否则"检查器坏了"会伪装成"全部合格"。

2. **实测值可以进报告当参考，不可以进判定当门槛。**
   范文摘要 506 字是"范文长这样"，不是"学校要求 ≤506 字"。

3. **不能自动做的事就不做，只报。**
   重编号、删重复条目、补页码——这些要么牵动全篇、要么会"造假"，所以只报不修。
   `action` 为 `null` 就是明确声明"这条只能人工改"。
