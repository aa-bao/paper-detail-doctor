# SOP｜开题一致性核对（怎么用、结果怎么读、怎么自证没作弊）

> **跨 skill 的 SOP。** 本文是**操作手册**：怎么建锚点档案、结果怎么读、L2 怎么交人裁、
> 怎么证明这个检查器不是硬编码。它**不重复**规则定义与 CLI 参数——那部分见
> `skills/proposal-consistency/SKILL.md`。
>
> 涉及：`proposal-consistency` + `workflow/audit_all.py -p` + `assets/anchors.example.yaml`
> + `tests/golden/proposal-consistency.yaml`。

---

## 一、什么时候用 / 什么时候别用

**该用**

- 答辩前自检："开题承诺的东西，正文真的做了吗？"
- 写作过程中大改过结构（并章、增加小节、缩样本）之后，想知道还差什么。
- 被导师说"感觉有点跑题"，需要一个可复核的清单而不是印象。

**别用（或者先降预期）**

- **开题报告本身很笼统**（只有一段"本文将研究 XX 问题"）：锚点抽不出来，能力会退化，
  大多会落「无法判定」。这不是工具坏了，是**输入不够**。
- **想判论证质量 / 观点对错**：它只查"说了没做"这类结构性关系，不判论证好不好。
- **想查正文内部的逻辑或事实错误**：它只查"开题 ↔ 正文"这一对关系。
- **想让它自动改稿**：所有 issue 的 `action` 一律为 `null`。一致性问题的终裁权在你和导师手里。

## 二、第一步永远是建锚点档案（不建就全是「无法判定」）

**检查逻辑是通用的**（七类锚点 A1–A7 × 三层判定 L1/L2/L3，代码里没有一篇论文的值）；
但"题眼是哪个词、点了哪些核心概念、引了哪些理论家、大纲里哪一章被并了节"——
**这是你论文的数据，不是工具的知识**。所以它们放在锚点档案里。

起步只要一条命令：

```bash
cp assets/anchors.example.yaml assets/anchors.local.yaml    # 然后照注释填
# 或放到正文同级：<正文目录>/.thesis-doctor/anchors.yaml，或设环境变量 PDD_ANCHORS
# 也可显式指定：audit.py -d 正文.docx -p 开题.docx --anchors my-anchors.yaml
```

### 填档案的操作顺序

**照这个顺序做，一趟就能填完**（对着开题报告看，不用来回翻）：

| 步骤 | 做什么 | 落到档案哪一段 |
|---|---|---|
| 1 | 看开题封面/题目，挑出 **2–6 字的独特题眼** | `A1_topic.tokens` |
| 2 | 抄开题点名的核心概念/关键词；记下正文里界定它们的那节标题片段 | `A2_concept` |
| 3 | 抄理论基础里点名的理论名或学者名；记下正文讲理论的那节 | `A3_theory` |
| 4 | 抄研究方法节的要素词（方法/对象/地点）；记下样本量那两句的**锚词** | `A4_method` |
| 5 | 抄开题大纲，找出四类结构性关系（见下）；记下正文对应位置 | `A5_outline` |
| 6 | 抄核心论断那句话的锚词；记下正文结论那节 | `A6_conclusion` |
| 7 | 什么都不用填 | `A7_refs`（脚本自己抓「不少于 N 条」） |

`A5_outline` 的四类关系各自要填什么（这四类正好对应四种结论）：

| 填哪一项 | 含义 | 会落到什么结论 |
|---|---|---|
| `expect_passed` + `expect_passed_label` | 双方**应同名出现**的结构标签（如几重逻辑的名字） | 一致 |
| `merged_chapter` + `merged_target` | 开题里有独立一级章、正文并成了节 | 改动 |
| `extra_tokens` + `chapter_heading` | 正文新增了小节、开题大纲里没有 | 偏离 |
| `missing_section` + `missing_fallback` | 开题大纲里有、正文没落地的条目 | 缺失 |

### 填档案的四个常见错误（照顺序排查，绝大多数"误报"都出在这）

1. **题眼填成了通用词**（"研究""分析""问题"）。必须挑独特词，否则双向命中的是巧合。
2. **值没跟文档逐字一致**。中文标点也要一致——文档里是全角逗号，档案里写半角逗号就匹配不上。
   匹配不到会被报成「缺失/偏离」或「无法判定」，看起来像程序出错，其实是填错了词。
3. **`thesis_heading` 填的片段不在正文标题里**。它是要拿去和标题树比对的，
   填了正文里没有的写法就定位失败。
4. **该留空的没留空**。`A1_topic.tokens` 留空时会退化为"从开题全文找《…》"，
   仍找不到才报无法判定——**不要为了"填满"而瞎填**。

> **未配置的锚点一律产出「无法判定」，绝不静默跳过、绝不判成「一致」。**
> 这是刻意的：静默跳过会被读成"这一项没问题"。所以看到一片「无法判定」，
> 正确反应是"档案没填全"，不是"没问题"。

## 三、结果怎么读 —— 五类结论各有各的动作

| 结论 | 严重度 | 你该做什么 |
|---|---|---|
| **缺失** | `error` | **最高优先**。开题写了、正文没做。要么补写，要么准备好"为什么不做"的说明。答辩最容易被问。 |
| **改动** | `warn` | 两边都有但不一致（数字变了、结构并了）。属自洽改动也要**准备一句说明**："为何从 X 收缩到 Y"。 |
| **偏离** | `warn` | 正文有、开题没有（新增小节）。多数是**合理扩充**——只要能说清它跟你的框架自洽就没问题。 |
| **无法判定** | `info` | **必须人工过一遍，不许跳过**。这是"没法判"不是"没问题"。 |
| **一致** | —（不产 issue，进 `meta.passed`） | 无需动作。报告里数的是**确定性通过项**。 |

**报告是证据卡形态**：每张卡给「开题原文引 + 正文原文引 + 期望/实际对照 + 建议 + 裁定位」。
设计意图就是**让你自己能判**，而不是替你判。

## 四、L2 语义项怎么交人裁（协议，别含糊）

脚本对 A2（概念）/ A3（理论）/ A6（预期结论）三类**不下结论**，输出一张 `verdict=待判` 的证据卡：
两侧原文 + `judgment_question` + `confidence: null`。

**宿主 agent（拿到卡的你）的裁定规则，写死不许含糊**：

1. 只许给 `等价` / `不等价` / `无法判定` 三种之一。
2. **置信度 < 0.7 一律归 `无法判定`**，转人工或转导师。
3. **不许给"差不多一致""基本对得上"这种模糊结论**——这是设计方案明令禁止的。
4. 判完把结论回写 issue 的 `verdict`，并填 `confidence`。

**为什么不在脚本里塞个 LLM 直接判**：一是只读脚本不内嵌模型，二是"一致性的最终裁定权在人和导师"。
脚本的职责只是**把证据摆齐、把该问的问题列出来**。

## 五、★ 怎么证明这个检查器没作弊（本项目最值钱的一条方法）

"召回 4/4、误报 0/4"这种数字好看，**但好看不等于没作弊**——一个把金标准答案硬编码进去的
假检查器也能拿满分。所以每次交付前必须做一轮**对抗性反向验证**：

> **改输入的内容，看结论跟不跟着变。**

具体做法：把两份文档复制到临时目录，**只改副本**，观察结论的增减方向。

| 注入动作 | 预期 | 说明 |
|---|---|---|
| 把开题里的文献承诺数改大（如 40 → 60） | **应新增**一条「缺失」 | 正文条数不够了 |
| 把开题里某条大纲条目删掉 | 对应的「缺失」**应消失** | 承诺没了 |
| 把开题的样本量改成与正文一致 | 对应的「改动」**应消失**、一致数 +1 | 差异被抹平 |

三项都随内容变化 → 证明确实在读文档。**任何一项不变，就说明有硬编码，必须查。**

两条纪律：

- **只在临时副本上操作，绝不改真实论文文件。**
- **绝对不许反过来改金标准 yaml 去迁就程序输出。** 金标准是"事实"，不是"期望"。
  如果召回率不满分，如实说明漏了哪条、为什么漏，然后**改判定逻辑**再跑。

## 六、跑分三指标怎么读

| 指标 | 定义 | 怎么用 |
|---|---|---|
| **召回率** | 金标准里的真差异被检出几个 | **最该盯的**。漏报最致命——答辩时被问到你答不上来的那种问题，就是漏报。 |
| **误报率** | 报出的差异（缺失/改动/偏离）里、金标准没有的占多少 | 误报让你白费功夫。偏高时**先查锚点档案填错**，再查规则。 |
| **定位准确率** | 给出的正文位置确实是那一处占多少 | 给错位置等于没用。偏低时查 `thesis_heading` 片段。 |

> **口径提醒**：`无法判定`（L2 待判）**不计入"差异"**，因此**不算误报**。
> 误报率只统计 `缺失/改动/偏离` 三类里金标准没有的。

金标准文件：`tests/golden/proposal-consistency.yaml`。
差异 id 形如 `A5-01`（前缀即锚点），`(anchor, type) → id` 的映射与定位关键词都由 yaml 推导，
**测试代码里不含任何案例数据**。跑法见 `tests/selftest_proposal_consistency.py`。

## 七、已知折扣（诚实清单）

1. **A2 的两项概念共用一张卡**：如果开题在概念一节里点了「A 概念」和「B（三维）构成」，
   脚本可能把它们合成一张 A2 证据卡，而不是各出一张。核的时候要在一张卡里同时看两项。
2. **金标准样本量小**：金标准是人工核对得来的一份文档。样本少意味着三指标**只能当趋势看**，
   不能当成"准确率 100%"的质量承诺。
3. **A7 只比数量**：它抓「不少于 N 条」与正文条数，**不比名单**。开题说"重点参考某某文献"
   而正文没引——这类问题它不报。
4. **L2 三类不下结论**：A2 / A3 / A6 一律交人。所以"一致 N 处"这个数字**只数确定性通过项**，
   看到"一致 4 处"而金标准列了 8 条对齐锚点，差的那些是**按设计交人审的 L2 项，不是漏判**。
5. **开题不完整时整体退化**：见第一节。
6. **不开题报告格式**：它读 docx。开题正文常常整个装在一个大表格里，脚本会自己遍历
   表格取文（对"开题也是个 docx"的任意用户都可复用）；但**只支持 docx，不支持 PDF**。

## 八、迁移到另一篇论文的改动清单

1. **建锚点档案**（第二节），代码一行不改。
2. **重建金标准**：人工把自己论文里真实存在的差异逐条记下来，写进
   `tests/golden/proposal-consistency.yaml` 的 `expected.差异`，并给每条补 `locate` 定位关键词。
   注意 id 前缀必须是锚点名（`A1`–`A7`），映射靠前缀推导。
3. **对齐锚点也记进去**（`expected.一致`）：哪些项是人核过确认一致的——
   它们是"不得被误报"的清单。
4. **跑一遍自检**，看三指标；再看第六节的诚实清单，确认折扣你都清楚。
5. **做一轮对抗性验证**（第五节）——不做这一步，等于没验收。
